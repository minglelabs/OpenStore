# OpenStore Product Record for Legal Use

This document fixes the core product description that should remain consistent across Apple communications, regulator packets, investor updates, and any later court filing. It is a factual working record, not legal advice.

## Source Basis Inside This Repository

The following points are directly supported by the repository as of 2026-03-20:

- `README.md` describes OpenStore as an open source alternative to the Apple App Store.
- `README.md` says the repository is intended to become a full marketplace product, not only a visual storefront.
- `README.md` also says the repository currently contains an initial storefront prototype for the consumer app.
- `README.md` says the current implementation is web-first and currently exposes storefront features through `/api/trpc`.
- The implemented product surface includes catalog discovery, app detail, developer detail, collections, search, library, account, reviews, and report flows.
- `package.json` identifies the current repository version as `0.1.0`.
- The current UI labels the product as a `Prototype`.

## Current Safe Product Description

Use this paragraph unless and until the product materially changes:

> OpenStore is an open source, web-first alternative app marketplace project. The current repository implements an initial storefront prototype that includes catalog discovery, app detail pages, search, library and account surfaces, reviews, and reporting flows through a web application backed by `/api/trpc`. The current repository does not, by itself, establish that OpenStore already operates a completed iOS installation, update, or alternative distribution stack on Apple devices.

## Future Product Ambition Already Expressed in the Repository

The repository openly states that OpenStore is intended to become a full marketplace product. The documented future scope includes:

- End-user storefront flows
- Account, billing, and library management
- Install and update flows
- Trust, reviews, and reporting
- A developer console
- An internal operations and moderation console

This future scope can be described as product direction, but it should not be described as already shipped functionality unless there is separate evidence.

## Pro-Competitive Positioning

The safest repository-backed framing is:

- OpenStore is designed to increase developer and user choice in app discovery and distribution.
- The current implementation focuses on storefront and catalog experiences, not on evading security controls.
- OpenStore's stated direction is to compete as a marketplace product, which is competition on distribution, merchandising, and user experience.
- The product claim should remain focused on choice, innovation, transparency, and lower dependency on a single platform-controlled storefront.

## Likely Apple Characterization and the Record Response

Apple is likely to characterize OpenStore as one or more of the following:

- A third-party app marketplace
- An alternative app-distribution product
- A product that could enable installation or execution of code beyond ordinary App Store distribution

The record response should be:

- Describe only the functionality that the submitted build actually contains.
- Separate the current shipped or submitted behavior from future roadmap language.
- Do not deny the competitive significance of OpenStore.
- Do not overclaim current device-level distribution capability if the submitted build does not contain it.

## What To Say Consistently

- OpenStore is an open source alternative app marketplace project.
- The current repository contains an initial storefront prototype.
- The product direction is to become a fuller marketplace product over time.
- Any statement about Apple review conduct must be tied to dated source material.

## What Not To Say Without Additional Evidence

- That Apple already rejected OpenStore
- That Apple already admitted a competitive motive
- That OpenStore already ships a complete iOS alternative marketplace
- That U.S. law already requires Apple to host third-party app marketplaces generally
- That Korean regulators have already accepted jurisdiction over a specific OpenStore complaint
